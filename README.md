# nocobase-multicore

Многоядерный режим для **NocoBase 2.x** (community-версия) и вкладка в настройках сайта с переключателем.

NocoBase — это один процесс Node.js, то есть одно ядро процессора. Здесь он запускается как **несколько процессов-воркеров на одном порту**, а всё, что должно быть общим между ними (события, блокировки, очереди, id, кэш), переезжает в Redis. Ядро NocoBase не патчится: всё сделано плагинами и небольшим запускающим процессом.

> Статус: `0.1.0`, проверено на NocoBase **2.2.33** на тестовом стенде (отчёт в [docs/TEST-REPORT.md](docs/TEST-REPORT.md)). Репозиторий приватный. Для ИИ-агентов, которые продолжат работу, начните с [AGENTS.md](AGENTS.md).

## Что внутри

| Что | Зачем |
|---|---|
| `packages/supervisor` | Лаунчер `nocobase-multicore`: запускает N воркеров (`node:cluster`), плавно меняет режим и число воркеров, перезапускает упавшие. |
| `@rosal-nb/plugin-multicore` | Вкладка **Настройки → Многоядерный режим**: переключатель, число воркеров, таблица процессов (CPU, память, лаг цикла событий), проверка кластера. |
| `@rosal-nb/plugin-pubsub-adapter-redis` | Общая шина событий между воркерами. |
| `@rosal-nb/plugin-lock-adapter-redis` | Блокировки между процессами. |
| `@rosal-nb/plugin-queue-adapter-redis` | Общая очередь задач (каждая задача — ровно одному воркеру). |
| `@rosal-nb/plugin-worker-id-allocator-redis` | Уникальные id воркеров, чтобы два процесса не выдавали одинаковые id записей. |

Когда режим выключен (или Redis не настроен), плагины-адаптеры ничего не меняют и NocoBase работает как обычно в одном процессе.

## Быстрый старт (Docker)

1. Соберите плагины: `node scripts/build.mjs` (нужен только `esbuild`).
2. Скопируйте `build/plugin-*` в `storage/plugins/@rosal-nb/` (имена папок оставьте как есть).
3. Скопируйте `.env.example` в `.env`, задайте пароли. Запустите стенд из `docker/docker-compose.example.yml`.
4. Подключите плагины: `yarn nocobase pm add @rosal-nb/<имя>` и `yarn nocobase pm enable ...` для всех пяти (команды — в [docs/OPERATIONS.md](docs/OPERATIONS.md)).
5. Откройте **Настройки → Многоядерный режим**, включите переключатель, выберите число воркеров, нажмите «Применить». Кнопка «Запустить проверку» прогонит самотест кластера.

Подробно про запуск на существующей установке (не Docker, свой compose, обновление) — в [docs/OPERATIONS.md](docs/OPERATIONS.md).

## Что важно знать

* Нужен **Redis** (переменная `REDIS_URL`) — один на все воркеры. Без него переключатель откажется включать режим.
* Приложение должно быть запущено через лаунчер `nocobase-multicore` (в Docker — подменой entrypoint, см. `docker/`). Иначе вкладка покажет предупреждение.
* Переключение «плавное»: новые воркеры стартуют, старые завершаются; до минуты.
* Изменения структуры данных (коллекции, поля) доходят до всех воркеров примерно за 1 секунду — это штатное поведение NocoBase. Ограничения самого NocoBase — в [docs/KNOWN-ISSUES.md](docs/KNOWN-ISSUES.md).
* Прирост даёт только то, что упирается в процессор JS (сериализация больших списков, расчёты). Если узкое место — база данных, ядер Node это не ускорит.
