# Отчёт о тестировании (стенд)

Дата: 2026-11-07. Стенд: выделенный сервер разработки, 2 vCPU, Docker; Postgres 16 + Redis 7.4 + `nocobase/nocobase:2.2.33`; приложение запускалось под `nocobase-multicore` (лимит памяти контейнера 1.6 ГБ). Postgres, Redis, генератор нагрузки и приложение делили эти 2 ядра, поэтому абсолютные цифры скромные — важны соотношения. Автоматического CI нет; всё выполнено вручную скриптами из `tests/` и `curl`.

## 0.2.0 (11.11.2026) — только локальные тесты, на стенде NocoBase ещё не проверено

## Пропускная способность
Запрос `bench_rows:list?pageSize=2000` (≈700 КБ JSON; нагрузка на JS-процессор), 8 параллельных клиентов, 15 с:

| Режим | запросов/с | p50, мс | p95, мс |
|---|---|---|---|
| cluster, 1 воркер | 6.2 | 1238 | 1938 |
| cluster, 2 воркера | **12.7** | 555 | 1179 |
| cluster, 3 воркера (на 2 ядрах) | 10.2 | 677 | 1821 |
| single (без Redis-адаптеров) | 6.7 | 1234 | 1530 |

Два воркера на двух ядрах дают ≈2× к одному; третий воркер на 2 ядрах уже не помогает (конкуренция за ядра с Postgres и генератором). Вход (`auth:signIn`) для замера не подходит: хеширование пароля идёт в пуле потоков libuv и уже использует несколько ядер в одном процессе.

## Дополнительные проверки (выпуск 0.1.0, финальная сборка)
* **Рабочие процессы:** триггер коллекции + узел «создать запись», `tests/workflow.js`: async 150/150 и 600/600, sync 40/40, дублей и потерь нет; одиночный режим даёт тот же результат.
* **Страховка:** отключение плагина при включённом кластере записывает `enabled:false`, сайт отвечает 200 всё время.
* **Удаление:** `uninstall.sh` при работающем кластере — сайт 200 (44/44), перезапуск контейнера штатный, сохранённые рабочие процессы продолжают срабатывать, остатков плагинов нет.
* **Установка:** `install.sh --docker` идемпотентен; загрузка tgz через менеджер плагинов (`pm:add`) работает; ссылки homepage видны в `pm:list`.
* Самопроверка дополнена проверкой уникальности worker id.

## Найденные и исправленные дефекты
9. Адаптер worker id ставился в `beforeLoad` — позже, чем ядро запрашивает id: воркеры получали случайные совпадающие id, ~27 % выполнений триггеров терялись (`id must be unique`) → установка в `afterAdd`, `release()` без действия.
1. Воркеры запускались без окружения CLI NocoBase (`Cannot find @nocobase/preset-nocobase package.json`) → `worker-entry.js`.
2. Воркер не завершался по SIGTERM (убивался SIGKILL через 30 с) → таймер `process.exit` в `worker-entry.js`.
3. Старый воркер при замене ещё получал новые соединения и отвечал 500 → `worker.disconnect()` перед SIGTERM.
4. Новый воркер открывал порт до загрузки приложения (503 «app is starting») → отложенный `listen()` до статуса `running`.
5. `listening` от unix-сокета IPC считалось готовностью воркера, старый воркер гасился раньше времени (502 от nginx) → учитываются только события с `port > 0`.
6. При смене режима поднимался лишний воркер, который сразу гасился → уменьшение числа воркеров выполняется до замены.
8. Server-only плагины без `dist/client/index.js` ломали весь интерфейс NocoBase (`Script error for "@nb-multicore/..."`, найдено при первом открытии в браузере) → сборка генерирует клиентскую заглушку.
7. В таблице воркеров у заменённого воркера был временный слот 1000+ → слот берётся из снимка лаунчера.

## Не проверено
Визуальный вид страницы в браузере; `install.sh --local` на реальной локальной установке; обрыв Redis; длительная работа (soak); загрузка файлов из нескольких воркеров; WebSocket/SSE; версии NocoBase кроме 2.2.33; MySQL.
