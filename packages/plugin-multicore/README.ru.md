# Плагин-менеджер — `@nb-multicore/plugin-multicore`

_Страница настроек с переключателем многоядерного режима, таблицей процессов и самопроверкой кластера._

**Основа**

Единственный плагин, с которым вы работаете напрямую. Добавляет в NocoBase страницу **Настройки → Многоядерный режим**, те же функции в виде API и следит за кластером.
Сам он ничего из функций NocoBase не переносит — это делают четыре плагина-адаптера.

**Функционал**

* **Переключатель и счётчик воркеров**, кнопка «Применить». Перед сохранением плагин проверяет, что Redis отвечает, что включены все четыре плагина-адаптера и что приложение действительно запущено под супервизором; иначе отказывает с понятной причиной.
* **Таблица процессов в реальном времени**: слот, PID, состояние, время работы, CPU %, память, лаг цикла событий, worker id (snowflake), хост. Данные — из heartbeat раз в 5 с через Redis (TTL 20 с).
* **Таблица адаптеров**: для каждого — состояние плагина (включён/выключен/нет) и действует ли адаптер в этом процессе на самом деле.
* **Самопроверка кластера** (кнопка «Запустить проверку» или `POST /api/multicore:selftest`): (1) сообщение pub/sub доходит до каждого воркера, (2) удерживаемая блокировка не пускает остальные воркеры, (3) 20 задач очереди обработаны ровно по одному разу, (4) у каждого воркера свой worker id.
* **Лимит памяти воркера** (`--max-old-space-size`) рядом с переключателем; при изменении воркеры заменяются по одному.
* **Сводка**: воркеры, пользователи онлайн, открытые вкладки, запросов в секунду, ошибки балансировщика, память сервера.
* **Перезапуск** одного воркера или всех по очереди — без простоя (`POST /api/multicore:restart {"slot": 1 | "all"}`).
* **Кто подключён**: нажмите на число пользователей воркера (или «показать» в сводке) — пользователь, логин, открытые вкладки, когда подключился, IP, воркеры. Берётся из WebSocket-соединений, которые NocoBase уже хранит (`GET /api/multicore:connections?slot=N`).
* **Журнал событий**: запуски воркеров, завершения с причиной, зависания с длительностью, перезапуски, ответы «Bad gateway».
* Воркер с занятым циклом событий остаётся в таблице с пометкой «не отвечает N с»; падения и зависания считаются по каждому воркеру.
* **Предупреждение**, если `(воркеры + 1) × DB_POOL_MAX` больше `max_connections` базы данных.
* **API** (право `pm.multicore`, у root есть): `GET /api/multicore:status`, `POST /api/multicore:apply {"enabled":true,"workers":3}`, `POST /api/multicore:selftest`, `GET /api/multicore:whoami`.
* **Страховка**: если этот или любой плагин-адаптер отключают или удаляют при включённом кластере, плагин записывает `enabled:false` в конфиг и сообщает супервизору, тот возвращается к одному процессу — сайт не работает с «недоустановленным» кластером.

**Как устроено**

Сервер: регистрирует ресурс `multicore` и ACL-сниппет, общается с супервизором через Node IPC (`process.send`), пишет конфиг атомарно (временный файл + rename). Клиент: обычный клиентский плагин NocoBase (React + Ant Design), страница настроек; язык интерфейса — английский или русский по языку NocoBase.

**Настройка**

Собственных настроек нет. Управляемый файл — `storage/multicore/config.json`. Права: Настройки → Роли → *Настройки плагинов* → *Многоядерный режим*.

**Безопасность / удаление**

Отключение/удаление сначала выключает кластер (страховка выше). Плагин **не создаёт таблиц в БД** и не меняет данные.

**Как проверить**

```bash
curl -s -X POST $BASE/api/multicore:selftest -H "Authorization: Bearer $TOKEN"   # ожидается "ok": true
curl -s $BASE/api/multicore:status -H "Authorization: Bearer $TOKEN"
```
